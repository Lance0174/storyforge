# 小说写作工坊：来源比较、内容设计与验证

日期：2026-09-27。本页是本轮内容研究与验证记录，不替代产品契约或三注册表。

## 边界与关联闭包

产品是独立小说创作的共享提示词资产层，覆盖构思、写作、修订、交接与包装，不进入世界衍生产品 S1/S2/S3。模板归全局 `promptTemplates`，作品仍归 `Work`；交接物是可选择的文本候选。本轮无世界版本引用、无新表、无媒资，也不增加正式写入字段。

入口：提示词库搜索/工坊筛选 → 模板预览/复制 → 工作流节点指定模板 → `assembleBoundPrompt` / `renderPrompt` → 现有 generation node。四个 `chapter.de-ai` 模板同时兼容正文的 `buildDeAIPrompt(text)`。正式作品修改仍遵守原来的候选、作者确认与 `adopt()`；工作流文本输出不等于作品已保存。

新增模板全部使用显式 `text` 材料槽和可选 `userHint`，可填写或由工作流入边提供，不暗中读取整个项目。需要项目自动上下文的任务仍可选原有 118 条小说阶段模板，它们通过登记的 `sourceKeys` 与 `assembleContext()` 装配。工坊不用组件私有查询拼上下文。`PROJECT_TABLES` 已登记全局模板和工作流生命周期；不改 schema。

## 与原库的差别

原库有 92 条基础/题材模板及 118 条小说阶段模板，已覆盖全流程，尤其擅长结构化规划与诊断。新增 28 条工坊内容针对作者实际操作中的小问题：一个材料槽即可起步、输出规模明确、先保真再改写、可局部使用。它们不是替代原库，而是补充“从报告到可写片段”的路径。

| 阶段 | 工坊任务 |
| --- | --- |
| 起步与定位 | 一句话起步；读者期待变成情节 |
| 世界与人物 | 规则进入麻烦；人物试镜；对白辨声 |
| 大纲与细纲 | 因果补桥；场景卡 |
| 正文 | 三个开场；按场景写正文；贴原文续写；对白交锋；动作戏；关系半步；悬疑场景 |
| 连载 | 自然章末钩子；准确交接卡 |
| 文风与去 AI 味 | 自有样稿文风卡；证据诊断；保真轻修；句群节奏；有效细节；对白分寸；情绪留白 |
| 返修与收束 | 连续性最小补丁；中段局部修复；结局兑现 |
| 试读与发布 | 首次阅读检查；书名与简介 |

四个正文去 AI 味工具只输出替换正文；诊断报告使用审校模块，避免诊断清单混进正文。新模板全部不激活，升级保留用户选择与用户副本。新内容按需加载，避免增大首页基础脚本。

## 使用与验证方法

- 在库内搜索“去ai味”也能匹配“去 AI 味”；可按“熔炉写作工坊”筛选。
- 工作流节点可指定同模块的一条模板，或保持跟随当前激活模板。填写一个材料槽即可；需要连接上游时，目标变量填 `text`。
- 模板输入与节点作者要求同时进入最终请求；未提供的作品事实不声称已读取。
- 先评估事实与范围，再评估语言：人物姓名/数量/否定是否保留，是否越过指定停笔处，是否把线索提前揭底，是否把全部角色写成同腔。
- 比较轻修前后应关注阅读收益与不必要改动；词频、字数、无套话都不能单独证明文学质量。

## 验证记录

定向回归覆盖 28 条模板的安装/升级幂等性、用户激活项与副本保留、必填材料、空白起步、工作流 `text` 入边、作者要求以及四个正文去 AI 味 adapter。6 个相关测试文件共 26 个用例通过。

本地 `npm run ci` 完成：765 个测试文件、4,057 个用例全部通过，覆盖率、架构/表/文档等检查、生产构建及体积门槛通过。交接模板最后一次文本调整另外通过 12 个提示词相关回归、类型检查、lint 和生产构建。远端 CI 状态以 PR 当前检查为准。

隔离浏览器执行 `PLAYWRIGHT_PORT=4188 npm run ci:e2e -- tests/e2e/prompt-craft-library.spec.ts tests/e2e/core-workflow.spec.ts`，共 54 个用例通过。新用例从搜索、模板预览开始，实际新建节点、选择模板、填写原文与限制、保存并刷新，再验证最终请求及结果。测试发现并修复了 React 严格模式下新节点 ID 与选中 ID 不一致的问题；同时确认工作流作者要求不再被绑定装配分支丢弃。浏览器断言使用模拟服务，只证明交互和请求合同，不证明文学效果。

### 真实模型抽测：三种任务、共七次生成

通过用户已配置的浏览器服务，在独立测试作品与新建的全局测试工作流中运行；未读取、导出 API Key，未采纳进正式作品。使用原创短材料，两个节点无连线，检查独立节点间没有素材混入。原材料和要求保存在本机测试工作流，未修改作者原有作品。

| 任务 | 首次结果与调整 | 调整后结果 | 仍需注意 |
| --- | --- | --- | --- |
| 保真轻修 | 输入含“沈宁、三张船票、没有签字、没下雨、钥匙不交周伯、周伯仍在门外”，并重复解释拒绝。第一次只删去部分重复，仍保留段尾同义总结；随后明确跨句处理重复结论 | 第二次保留六项事实，删去重复解释，未新增动作或物件；结果约 76 字 | 正式口吻的对白仍原样保留；“复杂的情绪”被删除，是否损失作者有意保留的情绪层次需要作者判断 |
| 场景正文与停笔 | 输入要求关门前修蓝伞、两根损坏/一根备用、另一根次晨补、递伞即停。首次约 312 字，但写成“收摊的时辰还早”，并在递伞后添加动作；随后补充场内事实核对与最后一句的动作边界 | 第二次约 343 字，保留蓝伞、数量和次晨修理安排，结束于递伞，没有新增秘密身份或混入前一节点船票钥匙 | 仍出现“晴好的天色意味着天快黑了”的不合理推断，临时固定另一根伞骨也是模型新增细节；不能把这次结果称为无需修改的成稿 |
| 章节事实交接 | 原文给定陆禾未交出钥匙、误信东门关闭但客观仍开，以及明确未发生的下一章计划。前两次多栏提取分别约 538/687 字，超出 350 字限制，还补出站位、落点、离场等未写事实；单纯补禁止项没有奏效，改为最多八条的三组“原文短引 → 直接含义” | 第三次约 289 字，保留未交钥匙、东门实际敞开、人物误信和未发生计划，不再补出站位、落点和离场 | 仍把旧绷带推断为“有伤”，部分引文经过改写而非逐字引用，必须对照原文确认；本工具只产出交接候选，不是自动事实抽取或记忆写入 |

本轮验证支持“模板可以找到、选择、装配和运行，代表性约束经过实际修订”，不支持“28 条文学效果全部验证”或“优于某商业产品”的结论。尚未进行跨模型、多题材长文的盲评；提示词约束不是形式证明，候选仍需作者审阅。去 AI 味的评价依据是事实、声线、节奏和阅读收益，不是检测器分数。
